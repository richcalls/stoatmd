# StoatMD · 存储、同步与迁移

2026-10-31 · 当前实现约定。采用跨平台 Rust / nsh 架构，首期交付 macOS。

一个笔记库有一个当前存储位置。macOS 提供本地文件夹、Dropbox 或 Google Drive，本地免费，Pro 解锁云盘。**iOS 没有本地文件 / 本地库功能**：付费应用一期仅提供 Dropbox / Google Drive；首启绑定云盘 → 选远程文件夹 → 进库，**不做本地库迁移**；设备保存离线缓存。笔记以普通 Markdown 文件存放，附件保持原始字节，云盘由用户自己的账号管理。

## 存储模式

| 模式 | 平台 | 文件位置 | 编辑与同步 |
|---|---|---|---|
| 本地 | **仅 macOS** | 用户选择的文件夹 | 直接读写该文件夹 |
| Dropbox | macOS / iOS | 用户选择的 Dropbox 文件夹 | 应用管理离线副本，联网后同步 |
| Google Drive | macOS / iOS | 用户选择的 Drive 文件夹 | 应用管理离线副本，联网后同步 |

云盘的离线副本位于平台应用数据目录 `com.stoatmd.app/libraries/`，由应用管理。设置展示提供商和远程路径。macOS 迁移到云盘后，原用户文件夹解除绑定，其后续修改与当前笔记库各自独立。旧版已有的双向绑定保留兼容读取，下一次迁移后进入上述模式。

macOS 购买流程尚待接入。开发配置 `purchaseRequired` 默认 `true`，环境变量 `STOATMD_PURCHASE_REQUIRED=0` 用于模拟 Pro。受限状态暂停云盘同步与冲突写入，离线副本仍可编辑，也可重新授权原账号并迁回本地。返回本地需要读取远程库，以包含远程独有文件；网络恢复后可以重试。

iOS 的云盘访问包含在应用售价中，`purchaseRequired` 对 iOS 始终为 `false`。首次启动**仅**显示 Google Drive / Dropbox（无本地选项），连接前进入授权引导；直接绑定所选远程文件夹并下载，**不执行本地库迁移**。设备缓存绑定当前云盘，支持离线读写。iOS 切换存储**仅**覆盖更换云盘或远程文件夹（云盘 ↔ 云盘），**不提供**迁回本机文件夹。

## 切换存储位置

### macOS

设置 → 存储使用分组列表，当前选项显示勾选。更改本地文件夹、切换云盘和返回本地均进入同一迁移流程。

1. 选择目标。云盘先检查权益，再授权、选择或新建文件夹。本地使用系统文件夹选择器。
2. 检查源与目标，显示位置、文件数量及大小，默认勾选「保留原位置数据」。
3. 暂停编辑、文件变更处理和新同步，等待已有同步与冲突处理结束，保存当前编辑内容。保存冲突需处理后重试。
4. 复制普通文件、二进制附件、嵌套目录和空目录。云盘来源先汇集离线副本与远程内容；同名差异保留两套资料。
5. 逐文件进行 SHA-256 校验，再次验证源快照与目标副本。云盘目标同时准备完整离线缓存。
6. 一次持久化当前根路径、云盘连接和可选清理任务，然后打开新位置。
7. 用户选择清理时，在切换成功后清理原文件；完成后恢复编辑与同步。

| 迁移方向（macOS） | 数据来源 | 新位置 |
|---|---|---|
| 本地 → 本地 | 原目录 | 新本地目录 |
| 本地 → 云盘 | 原目录 | 远程目录及应用离线副本 |
| 云盘 → 本地 | 离线修改及远程文件 | 本地目录 |
| 云盘 → 云盘 | 离线修改及原云盘文件 | 新云盘目录及应用离线副本 |

### iOS

**无本地库、不做本地库迁移。** 设置 → 存储仅列出 Google Drive / Dropbox。首启：授权 → 选/建远程文件夹 → 下载进库。之后若更换云盘或远程文件夹，走云盘 ↔ 云盘切换（复制离线修改与远程内容到新位置并重建缓存）；**不出现**「返回本地」或本机文件夹选择器。

相同路径、相同内容可复用。遇到同名差异、文件与目录冲突或大小写冲突时，整套迁入资料置于内容指纹命名的 `Imported library …` 子目录，保持相对附件链接。中断重试可复用内容一致的已复制文件。目标已有资料保留。

源与目标应为独立目录。相同目录和父子嵌套目录会被拒绝。隐藏文件、`node_modules` 与应用配置留在原处；符号链接和特殊文件会阻止迁移并显示错误。Google 原生文档、快捷方式等特殊云文件属于提供商数据，当前迁移处理普通文件。

## 失败与清理

提交前失败：原存储继续使用，源文件保持原样。目标可能留下已复制文件，用户可重试。临时离线缓存尽力回收。

提交后清理失败：新存储继续使用，待清理任务保存在当前存储记录中，重启后可重试或选择保留剩余文件。发起下一次迁移前需先处理该任务。

清理逐项检查源版本、源哈希和目标哈希，且只处理迁移收据中的原文件。变化的源文件、变化或缺失的目标副本、无关文件及目录保留。macOS 本地原文件移至废纸篓；远程清理使用提供商的删除保护（Dropbox 版本条件、Google 版本检查及 ETag 条件回收）。缺少条件删除支持时保留原文件并提示清理重试。当前 Linux / Windows 的本地废纸篓操作仍待接入。

## 持久化与同步

`storage.active` 是权威记录，包含版本、当前根路径、单个云盘连接和清理任务。更新该记录是迁移提交点，损坏记录会显示错误。同步锚点与最后同步时间按连接实例隔离，旧版 `sync.connection` / `sync.base` / `sync.lastAt` 仅用于兼容读取。

OAuth 令牌通过 `TokenVault` 管理，macOS / iOS 使用系统钥匙串。重新授权原存储时检查账号，选错账号会保留已有令牌。清理重试需要原位置的授权。

日常同步覆盖 Markdown、普通附件和目录。保存后防抖上传，启动和定时拉取。双方修改同一路径时逐文件处理：保留本地、保留云端、两边都留。迁移使用独立目录保存碰撞资料；日常同步使用文件级冲突选择。

## 验证范围

自动化覆盖迁移四类方向、二进制字节与空目录、碰撞目录和重试、源及目标变化、离线缓存失败、选择性清理、授权账号保护、免费入口以及本地迁移 UI 与持久化。真实云盘账号的 OAuth、配额、条件删除和网络恢复仍需配置凭据后端到端验证。

# StoatMD 技术设计 v1

> 曾用名 LoomMD。仓库：[`richcalls/stoatmd`](https://github.com/richcalls/stoatmd)。
> 对应产品设计：定稿见 `docs/product/` 与 `docs/ui-v1/`。

## 目标与非目标

**目标（v1）**

- nsh 混合工程（Rust + TSX），跑通 macOS + iOS
- macOS 自选本地文件夹；iOS 连接 Google Drive / Dropbox，下载离线缓存；读写普通 `.md`
- 源码编辑 + 仅编辑 / 仅预览 / 分栏预览
- 两栏（Mac）与导航栈（iPhone）；深色跟系统；停顿自动保存

**非目标（v1 工程实现）**

- macOS 买断购买流程（iOS 为付费应用，云盘访问包含在售价中）
- **MCP / AgentBridge（产品已决定不做）**
- 所见即所得、插件、幻灯片、自建服务端

> **产品已定（交叉引用）**：不自建同步服务器；本机文件夹是真相；产品**多语言、出海**（至少中英）；一期提供商仅 Google Drive + Dropbox（均主推，服务全球用户与 Personal Agent）；**不做 iCloud**；macOS 云盘同步买断；iOS 付费应用直接连接云盘，设备保存离线缓存；冲突必须弹选、禁止静默覆盖；**不做 MCP**（无自有服务器，远程 Agent 无法挂本地 MCP；Personal Agent 走云盘文件）。详见 [product/PRODUCT.md](./product/PRODUCT.md) 与 [product/SYNC.md](./product/SYNC.md)。

## 技术栈

| 层 | 选型 | 说明 |
|---|---|---|
| UI 框架 | [nsh](https://nsh.dev) ≥ 0.3，`nsh init --template mixed` | 官方推荐混合：Rust 重活 + TSX 界面 |
| 源码编辑 | `nsh/base` **Editor** | 语法高亮、行号、查找；Markdown 当纯文本编辑 |
| 预览 | `nsh/base` **TextView**（`markdown`） | 原生渲染；v1 以 GFM 为准 |
| 布局 | **Resizable** / **List** / **NavStack** | Mac 两栏（文件树 + 编辑）；iOS 用导航栈 |
| 桌面壳 | `nsh/desktop` | 菜单、快捷键、窗口标题 |
| 文件 | Rust + 标准文件能力（沙箱声明） | 路径限制在库根内 |

## 模块划分

```
stoatmd/
  crates/stoatmd-core/    # Rust：Vault、索引、监视、写盘
  src/                    # TSX：壳、列表、编辑器、预览
  nsh.json
  docs/
```

（工程目录若仍暂用 `loommd` 命名，实现阶段再统一为 stoatmd。）

### `Vault`（Rust，v1 实现）

- `open(root)` / `list` / `read` / `write` / `create` / `rename` / `delete`
- 路径规范化，禁止逃出 `root`
- 文件监视 → 事件给 UI；当前文件有未保存冲突时由 UI 提示保留或重载
- App 偏好只存上次 `root` 等极少项

### UI（TSX）

- Mac：左树 / 中列表 / 右 `Editor` + `TextView`（`Resizable`）
- iPhone：`NavStack`：库 → 列表 → 编辑；预览切换
- iPad：近 Mac 分栏

### 同步接口（产品约束已定）

- `SyncProvider`：一期仅 Drive / Dropbox（见 [product/SYNC.md](./product/SYNC.md)；**不做 iCloud**）
- **不做** `AgentBridge` / 本地 MCP sidecar；远程 Agent 仅通过用户云盘（Drive/Dropbox）读写同一库；**不做 iCloud**

## 可行性结论（相对妙言级源码+预览）

| 能力 | 结论 |
|---|---|
| 源码编辑 + 分栏预览 | **可做**：Editor + TextView + Resizable |
| 列表 / 导航 | **可做**：List + NavStack |
| 文件存储 | macOS 自选目录；iOS 云盘缓存和系统文件导入导出 |
| 框架成熟度 | **风险**：nsh ~0.3，需真机验证 Editor 手感与性能 |

**建议顺序**：空壳冒烟（Editor+TextView 分栏）→ 接 Vault → 接云盘与离线缓存 → 双端验收。

## 风险与对策

1. **nsh API 变动**：锁版本；大升级单独评估
2. **iOS 云盘授权**：验证系统授权、钥匙串与离线恢复
3. **大文件 / 长文**：Editor 虚拟化与写盘防抖要测
4. **预览扩展语法**：Mermaid/LaTeX 不进 v1，避免卡首发
